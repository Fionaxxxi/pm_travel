1.5 主路径与进度控制重点
建议主路径为 A → B → M1 → D → F → G → M2 → H → I → J → M3 → P → Q → T → 完成。该路径连接范围基线、用户偏好、推荐与初始规划、动态重规划、系统测试、版本冻结和最终验收，与详细 WBS 中给出的主路径保持一致。
1.5.1 关键汇合点
M1 是需求和技术定义的汇合点。范围、原型、数据字典或接口契约未通过评审时，W3 的并行开发不得作为正式基线继续推进。
M2 是基础开发的汇合点。工程骨架、景点与画像数据、推荐算法、行程与地图展示以及测试准备必须共同支撑首次端到端演示。
M3 是三条并行智能能力链的汇合点。动态重规划、自适应解说、兴趣推送与反馈任一分支未完成，均不能认定核心业务闭环形成。
1.5.2 发布前依赖
发布候选版冻结 Q 同时依赖回归测试与交互修订 P，以及环境和交付文档准备 R。这样可以避免仅以功能通过替代部署可复现性和文档完整性。W8 的课程报告、答辩演练和最终验收必须在候选版冻结后进行。
1.5.3 持续活动
沟通决策、风险问题、依赖和变更管理在 W1–W8 持续开展；缓存日志、单元与接口测试、缺陷管理及文档同步从基础开发阶段持续到发布。它们在图中以虚线支持轨表示，不作为单一完成到开始节点，但其结果会影响每个里程碑是否通过。
1.5.4 使用建议
任务看板仍以详细 WBS 三级工作包为最小单元，网络图活动编号作为汇总视图。
周会更新活动状态时，应同步检查紧前活动是否真实完成，以及里程碑通过证据是否齐全。
若主路径活动预计延期，应先调整资源或压缩非关键活动；涉及范围、接口或里程碑的变化需进入变更评审。

2.11 成本蒙特卡洛模拟
2.11.1 模拟目的与范围
本次模拟用于估计原始资源预分配方案在不同直接费用情景下的总成本分布，并确定P80预算参考值。总成本由人力机会成本与直接费用构成。
人力机会成本按计划工时与内部核算单价计算：
CH=80×60+104×55+104×65+112×70+96×50=29,920
直接费用的最可能值合计为2,200元，因此原方案的确定性成本基准为：
C0=29,920+2,200=32,120
现有资料没有提供与人时对应的完整工时三点估计，也没有明确任务持续时间与成员投入小时之间的转换关系。本次将人力成本固定为29,920元，只对已有三点数据的六项直接费用抽样。因此，得到的是“给定计划人力成本条件下，直接费用波动引起的总成本分布”，不包含人员返工、延期追加工时等风险，也不用于推断项目按期概率。

3 、三点估算与调度计划完善
3.1 估算方法说明
采用计划评审技术（PERT）三点估算法：
乐观时间 O：一切顺利、无阻塞、无返工的理想工期
最大可能时间 M：正常情况下、遇到常见问题但能解决的工期
悲观时间 P：遇到技术卡点、需求变更、环境故障等最坏情况的工期
期望工期 = (O + 4M + P) / 6标准差 = (P - O) / 6
估算依据：
各工作包的技术难度系数
成员性格模型带来的效率偏差（MBTI分析）
已知风险项（RAG接口、路径规划、联调集成）

4.1 项目目标与调度原则

本计划使用教学周，不指定实际开工日期。活动工期采用三点估算的期望值，跨周条形表示执行窗口，不表示连续占满全部周次。

5、角色能力系数估算
5.1 估算方法说明
基于MBTI性格模型 + 软件工程基本能力维度，为每个成员估算角色能力系数。
能力维度（5个维度，每项1-5分）：
编码实现：写代码、调试、落地实现能力
设计分析：架构设计、需求分析、方案对比能力
文档写作：文档撰写、报告整理、汇报材料能力
沟通协作：会议表达、团队协作、冲突处理能力
执行推进：进度把控、闭环跟踪、验收门禁能力
能力系数 = 各维度加权得分，用于任务分配时的效率参考。
说明：系数仅用于分工参考，不代表成员真实水平高低，而是"在什么类型任务上效率更高"。

6.7与蒙特卡洛成本报告的衔接
第2.11节采用六项直接费用的三角分布，固定原方案人力成本29,920元，独立抽样100,000次，得到原方案P80总成本32,599.13元，按百元向上取整为32,600元。本节继续使用35,200元作为自行设定的预算比较上限，该数值不代表蒙特卡洛模拟结果。
推荐方案A0+B1+C1+D2的人力成本为29,970元，比原方案增加50元。若六项直接费用分布保持不变，且人力成本继续视为固定数，则推荐方案每轮总成本均比原方案增加50元，因此P80总成本为32,649.13元，按百元向上取整为32,700元。相对于推荐方案确定性成本32,170元，P80差额为479.13元；采用取整预算时，预留额度为530元。
本次模拟仅覆盖直接费用波动，未计入资源转交可能增加的返工工时及费用相关性变化。如果实际工时或费用分布发生变化，应更新输入并重新模拟。37工作日仍是确定性容量模型估计，不是P80工期，也不代表按期完成概率。
6.8实施前确认与结论
在采用推荐方案前，需确认B1/C1/D2对应支撑工作确实存在且能够转交；确认成员每周最多20小时的可用投入；将工作包依赖、W7候选冻结和测试完成条件加入详细调度，并验证关键质量要求。
在上述近似条件下，已实际完成后向动态规划计算与27组合枚举核对。推荐分配为A0+B1+C1+D2，估计37工作日、32,170元；最便宜方案为40工作日、32,020元。该结果提供可复核的资源取舍依据，待详细WBS与成员数据确认后再更新为实际执行计划。
附：复核流程
从原分周表按两周合并五角色人时。
根据扰动表逐项增减人时，按费率求和生成模式成本。
以最大角色人时/4向上取整计算阶段容量工期。
逐阶段用“最早开始边界与上一完成日取较大值，再加阶段工期”计算完成点。
后向动态规划保存每个状态的最优后续模式；完整枚举27组合交叉核对。
用选中模式的角色人时与费率再次核对成本。
